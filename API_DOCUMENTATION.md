# EC2 Agent API Documentation

This repository is a detached runtime. Only the contents of `EC2/` are deployed to the EC2 host, and every agent under `EC2/agents` must run independently from this repo alone.

## Base URL

- Public host: `http://13.206.83.175`
- Internal services run behind Nginx on `127.0.0.1:<port>`

## Common Conventions

- Requests use `Content-Type: application/json`
- Most actions accept `taskId`, `userId`, and `agentId`
- Business failures normally return HTTP `200` with `{"status":"failed","error":"..."}`
- OAuth-protected agents return HTTP `200` with `status: "action_required"` when the user is not connected

## Auth Contract

OAuth agents own their auth lifecycle directly on EC2 and expose:

- `GET /<slug>/auth/login?handoff=<signed-token>`
- `GET /<slug>/auth/callback`
- `GET /<slug>/auth/status?handoff=<signed-token>`
- `POST /<slug>/auth/logout`

Supported OAuth slugs:

- `teams`
- `google`
- `notion`
- `canva`
- `discord`
- `dropbox`
- `github`
- `gitlab`
- `jira`
- `linkedin`
- `zoom`

The `handoff` token is generated by the web app/backend and signed with `AGENT_OAUTH_SHARED_SECRET`. EC2 validates it before starting OAuth.

Stored credentials are persisted in Firestore at:

- `users/{uid}/providerConnections/{provider}`

Stored fields:

- `accessToken`
- `refreshToken`
- `expiresAt`
- `scopes`
- `metadata`
- `bundleId`
- `connectedAt`
- `updatedAt`

## Standard OAuth Failure Response

```json
{
  "status": "action_required",
  "type": "oauth_required",
  "message": "Google access token is missing. Please connect your Google account.",
  "error": "AUTH_REQUIRED",
  "provider": "google",
  "auth_url": "http://13.206.83.175/google/auth/login",
  "agentId": "google-agent",
  "bundleId": "google-bundle"
}
```

## JS-Parity Notes

- `canva-agent` intentionally returns `Canva integration is coming soon.` because that is the current JS source-of-truth behavior.
- `freshdesk-agent` returns stub/mock payloads matching the current JS tool.
- `jira-agent` returns stub/mock payloads matching the current JS tool instead of live Atlassian API calls.

## Smoke Examples

Teams health:

```bash
curl http://13.206.83.175/teams/health
```

Todo list:

```bash
curl -X POST http://13.206.83.175/todo/action \
  -H "Content-Type: application/json" \
  -d '{"taskId":"smoke-1","userId":"smoke-user","agentId":"todo-agent","action":"list_tasks"}'
```

Google action without connection:

```bash
curl -X POST http://13.206.83.175/google/action \
  -H "Content-Type: application/json" \
  -d '{"taskId":"smoke-2","userId":"smoke-user","agentId":"google-agent","agent_type":"gmail","action":"read_emails"}'
```
